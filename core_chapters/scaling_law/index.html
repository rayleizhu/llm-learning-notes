一句话理解

Scaling Law 描述资源与损失的关系；计算最优 Scaling Law 利用这种关系，求给定预算下的最佳分配与最低损失。后者是前者的一种应用，不是全部。

01
LAYER 1 · DESCRIBE THE RELATIONSHIP

第一层：资源规模如何影响 loss？

这一层先不问预算怎么分，而是用实验描述：在数据分布、架构、训练方法与评测口径可比时，给定 N 和 D，最终 loss 大约是多少？

1.1 从实验拟合资源与损失的关系

Chinchilla 风格的一种联合经验模型如下。帽子符号 L̂ 表示预测值，E、A、B、α、β 都依赖实验设置，不是通用常数。

L̂(N, D) = E + ANα + BDβ
E：拟合的渐近下限A/Nα：模型容量限制项B/Dβ：数据 / 训练不足项

固定 D，增加 N

参数项降低，预测 loss 下降；但数据项仍然存在，不能只靠扩大模型消除它。

固定 N，增加 D

数据项降低，预测 loss 下降；但容量限制仍然存在，持续多读数据的收益会递减。

这一层的输出是一个关系函数，而不是一个最优配置。如果没有预算或其他约束，该模型倾向于让 N、D 都继续增大；要回答“多大最合适”，还需要第二层。

1.2 用单个方向的曲线理解幂律

先固定另一个变量，观察一个资源方向。用 x 表示变化的规模、α 表示该方向的指数，曲线可简写为：

L(x) = Ex + Ax−α
x：某一种资源规模Ex：该曲线的有效下限A, α > 0：拟合系数

例如固定 D 改变 N 时，Ex = E + B/Dβ，不等于联合模型中的 E。改变 D 的方向则对应指数 β。下方滑块只用于说明幂律，不改变第二层计算器的论文拟合系数。

规律可预测，收益会递减

定义相对此曲线下限的可约损失 ΔL = L − Ex。资源扩大 k 倍，ΔL 变成原来的 k−α 倍；同样的倍数增长带来相同的相对改善，但绝对降幅越来越小。

例如 α = 0.30 时，资源翻倍只让可约损失下降约 19%，而不是让模型“聪明一倍”。

直线来自坐标，而非线性收益

两边取对数：log ΔL = log A − α log x。在双对数坐标中，这就是一条斜率为 −α 的直线。

有非零下限时，应该画 L − Ex，而不是默认总损失 L 在 log-log 图中也是直线。

02
LAYER 2 · OPTIMIZE UNDER A BUDGET

第二层：固定预算，怎样让 loss 最低？

现在把第一层拟合好的 L̂(N, D) 当作目标函数，给定训练计算预算 C。对稠密模型采用 Ctrain ≈ 6ND 的近似，只在预算允许的配置里找最小值。

(Nopt, Dopt) = arg minN,D > 0; 6ND ≤ C L̂(N, D)
L̂min(C) = L̂(Nopt, Dopt)

因此答案有三个：模型应该多大、训练 token 应该多少、最低预测 loss 是多少。在这个正系数、连续规模的简化模型里，最优解用满预算，所以可令 D = C/(6N)，把问题变成沿固定算力曲线寻找谷底。

注意：“最低 loss”有条件

L̂min(C) 是当前拟合函数在预算约束下的最小值，不是无条件保证的真实训练结果；它也不是联合模型的渐近下限 E。换数据分布、训练方法或模型架构，应重新校准第一层的关系。

2.1 交互实验：一笔预算，三个最优答案

先调整预算，看 Nopt、Dopt 与 L̂min 怎样变化；再保持预算不变，偏离最优参数量，观察当前 loss 为什么升高。第一层负责算出曲线上的每个点，第二层负责选出最低的那个点。

把每笔预算的最优点连起来，会得到什么？

对第一层的联合幂律模型求解，可得到最优资源分配与最低损失随预算变化的规律：

Nopt ∝ Cβ/(α+β)   Dopt ∝ Cα/(α+β)
L̂min(C) − E ∝ C−αβ/(α+β)

这条 loss–compute 曲线要求每笔预算都重新选择最优 N 与 D，不是固定模型只延长训练。比例常数仍由 A、B 等系数决定；只知道指数，不能算出绝对的模型大小或最低 loss。

2.2 从 Kaplan 到 Chinchilla：最优配比的演进

两篇论文都研究资源与 loss 的关系，也都讨论计算最优分配。下面比较的是第二层的最优路径，不是说 Kaplan 只研究第一层、Chinchilla 才研究第二层。

关键突破

Chinchilla 并非首次提出 Scaling Law，而是改进第一层的实验与拟合，修正第二层的模型—数据配比，并用大规模训练验证：同样的预算，更小但训练更多 token 的模型可以更强。

THE CHINCHILLA EXAMPLE

70B 参数，1.4T tokens

相较 280B 的 Gopher，Chinchilla 用约四分之一的参数、更多的训练 token，在论文所报告的相近训练计算预算下，取得更好的多项评测结果。

“20 tokens / parameter”该怎么用？

它是 Chinchilla 风格计算最优的常见粗略起点，不是数据上限，也不代表模型收敛。若目标是低推理成本，较小模型训练更多 token 可能更合算。

应用
FROM FITTING TO DECISION

先校准第一层，再使用第二层

最优配置是否可信，首先取决于资源与 loss 的关系是否拟合可靠。实际训练时，把两个层次落实为下面四步。

第一层 · 01

固定评测口径

确定语料混合、分词器、上下文长度、验证集与 loss 单位，避免把口径变化当成规模收益。

第一层 · 02

拟合资源与损失

用 N × D 实验网格拟合 L̂(N,D)，匹配学习率调度，并用留出实验检查残差和外推误差。

第二层 · 03

加入预算，求三个答案

指定 C，求 Nopt、Dopt 与 L̂min(C)。围绕候选配置做验证，不把预测当保证。

第二层 · 04

补齐实际约束

加入数据、显存、吞吐与推理需求。目标或约束改变时，重新求解；训练最优不等于部署最优。

补充说明

A
WHAT ARE WE MEASURING?

Loss 是预测误差，不是能力总分

自回归语言模型在给定前缀时，为下一个 token 分配概率。常用的交叉熵损失，是正确 token 的负对数概率的平均值。

L = −𝔼[log pθ(xt | x<t)]
自然对数：单位为 nats/token以 2 为底：单位为 bits/token

使用自然对数时，困惑度 PPL = exp(L)。如果 loss 降低 Δ，困惑度乘以 exp(−Δ)，而不是简单减去 Δ。比如 L 从 3.0 降到 2.9，PPL 大约从 20.1 降到 18.2。

比较之前，先确认四个条件

  • 相同分词口径：不同 tokenizer 的 token 粒度不同，nats/token 不宜直接横比；跨分词器比较可考虑统一字节口径，并说明数据预处理。
  • 相同评测分布：验证集、语料混合与上下文长度变化，都可能改变 loss 的基线。
  • 相同训练条件：学习率调度、优化器与数据质量影响拟合系数，不应被误归因于参数量。
  • 训练/验证分离：训练集上的低 loss 可能来自记忆或重复；必须检查验证 loss、去重与评测泄漏。
关于 Chinchilla 的原始测量

其规模实验使用平滑训练损失；论文在近似单遍、数据充足的实验设定下，将其视作测试损失的无偏估计。这不意味着在多轮重复训练中，训练损失总能替代验证损失。

具体怎么平滑？附录 D.1 明确写道：We use Gaussian smoothing with a window length of 10 steps to smooth the training curve. 即高斯平滑，窗口长度为 10 个训练 step。

这是对记录下来的训练 loss 曲线做后处理，可理解为用邻近 step 的 loss 做高斯加权平均，以减小随机波动。方法 1 随后对曲线插值，提取各计算预算下的最低损失包络。它不是 label smoothing，也不修改反向传播使用的 loss。

实现细节与适用范围：10 steps 是原文的窗口长度，不能直接当作标准差 σ = 10；该处未给出标准差、窗口是否居中或端点处理方式。这个具体设置写在方法 1 的附录 D.1；方法 2 也使用平滑后的最终 loss，但对应段落没有单独说明平滑参数，不宜断言所有分析都采用完全相同的实现。

原始依据：附录 D.1；处理流程见 §3.1，方法 2 见 §3.2 ↗

联合拟合中的 E 是针对指定分布、分词与上下文设定的渐近下限参数，可作“不可约损失”的模型化解释；它不是已经精确测得的、所有自然语言共享的熵常数。

B
THE COMPUTE APPROXIMATION

C ≈ 6ND 从哪里来？

对以大规模矩阵乘法为主的稠密 Transformer，一个乘加常计为两次浮点运算。按每个 token 估计：

训练主干矩阵运算的常用数量级近似
阶段每个 token 的计算量直观解释
前向传播约 2N FLOPs每个权重参与乘法与加法
反向传播约 4N FLOPs权重梯度与激活梯度，约两倍前向
合计 D 个 token约 6ND FLOPs每 token 运算量 × token 总数

例如 7B 参数训练 140B tokens，近似计算量为 6 × 7 × 109 × 140 × 109 = 5.88 × 1021 FLOPs。这只是运算总量，不是 GPU 数量或训练天数。

FLOPs 不等于 FLOP/s，更不等于账单

t ≈ CnGPU · Fpeak · MFU
C：FLOPsFpeak：每秒 FLOPsMFU：模型算力利用率

如果 C 使用模型有用运算口径，应搭配同口径的 MFU，避免重复计算重算开销。通信、内存带宽、并行策略与故障恢复都会改变实际效率；该式只是粗估。

什么时候 6ND 不够用？

长上下文注意力的二次项、词表投影、小模型中的 embedding 占比、激活重算、稀疏路由和硬件效率都需要单独检查。MoE 的计算更接近激活参数量相关的运算，但模型容量还涉及总参数、专家数和路由；不能仅替换一个 N，就复用稠密模型的 loss 系数。

参数口径也要一致：Kaplan 主要使用非 embedding 参数；Chinchilla 的详细 FLOPs 与参数统计包含 embedding。引用常数前应先核对论文定义。

原始依据：Chinchilla 附录 F 的运算量统计 ↗
C
DERIVING THE OPTIMUM

固定算力，求最优 N 与 D

假设 A、B、α、β 均为正，使用联合经验模型 L̂(N,D) = E + AN−α + BD−β，并固定 C = 6ND。以下是这个假设模型的数学结论，而非独立于实验的普遍定理。

第一步：把两个变量变成一个

由约束得到 D = C/(6N)，代入：

L̂(N) = E + AN−α + B(6N/C)β

随 N 增大，参数限制项下降，数据/训练不足项上升。对 log N 求导并令其为零：

αANα = βBDβ
平衡的是边际改善，而不是两项数值必须相等

令 u = log N，非恒定项是两个正系数指数函数之和，二阶导数严格为正；因此在无额外约束、N,D > 0 的连续空间中，这个驻点是唯一的全局最小值。实际可选模型大小是离散的，还需做邻近配置比较。

第二步：解出计算最优路径

Nopt = G(C/6)a
Dopt = G−1(C/6)b
a = β/(α + β)b = α/(α + β)G = (αA/βB)1/(α+β)

因为 a + b = 1，所以两者的乘积与 C 成正比，符合预算约束。只有当 α ≈ β 时，才得到 N、D 大约都随 √C 增长。注意：参数规模指数取的是 β/(α+β)，并不是 α/(α+β)。

把最优解代回，还得到最优路径上的可约损失：L̂opt − E ∝ C−αβ/(α+β)。这里的“计算幂律”依赖于持续调整 N 与 D，不是固定一个模型只延长训练的曲线。

不要把两种精度、三种方法混在一起

用上述舍入的 α = 0.34、β = 0.28，可得 a ≈ 0.452、b ≈ 0.548；论文表 2 对方法 3 报告的是约 0.46/0.54。主页面按公开舍入系数计算，不声称精确复现原始未舍入拟合，也不强行让该最优点满足 D/N = 20。方法 1、2 与方法 3 的预测本就不完全一致。

更大的预算常已超出用于拟合的小规模实验范围。漂亮、平滑的曲线不代表外推可靠；系数误差、曲率与数据分布变化都可能改变预测。

D
A RULE OF THUMB, NOT A CONSTANT

为什么 20:1 不是定律？

Chinchilla 的实际配置为 70B 参数与 1.4T tokens，比例为 20。论文方法 1 的若干预测也接近这个量级，因此 D ≈ 20N 常被用作快速估算。

然而，“参数与数据大致同比例扩展”约束的是指数，并不能单独确定比例为 20。即使 α = β，固定比值也仍取决于 A、B；当 α ≠ β 时，D/N 还会随计算预算变化。

Dopt/Nopt ∝ C(α−β)/(α+β)

如果只是做 20:1 的纸面估算

明确假定 D = 20N，再结合 C ≈ 6ND，得到 N ≈ √(C/120)，D ≈ 20√(C/120)。它适合建立数量级直觉，不是主页面拟合函数的精确最优解。

数据更多，不代表过拟合

“超过训练计算最优 token 数”只说明目标偏离了那条预算最优路径。继续训练可能仍改善验证损失，不等于已经过拟合；是否过拟合应看训练/验证差异。

更多 token，不总是更多信息

D 是处理量。重复采样、低质量内容与全新高质量样本的收益不同。数据受限时应区分独特 token 数和重复轮数。

小规模 Chinchilla 拟合实验主要研究数据充足、近似单遍训练的区间。实际 1.4T 训练中，各语料子集的重复程度并不完全相同；不能据此认为原始联合模型已完整描述多轮重复的收益。

Scaling Data-Constrained Language Models 进一步研究了数据受限场景：适量重复可以有效，但反复增加轮数的收益会递减；不要把其特定实验中的重复轮数也当成普适阈值。

E
BUILD YOUR OWN EVIDENCE

如何拟合自己的 Scaling Law？

最佳用法不是复制历史常数，而是在自己的语料、架构与训练设置上，用便宜实验约束昂贵决策。

  1. 固定口径，记录所有变量锁定 tokenizer、验证集、上下文长度和数据配比。每个实验记录 N、已处理 D、实际 FLOPs、训练与验证 loss、学习率调度、随机种子和吞吐。
  2. 设计 N × D 网格，而非只增大 N在多个预算上训练多种模型大小，让每条 IsoFLOP 曲线覆盖最优点两侧。只有一侧的单调趋势，很难可靠定位谷底。
  3. 让学习率周期与训练长度匹配把一次很长训练的中途 checkpoint，直接当作该较短训练预算的最优终点，会造成偏差。Chinchilla 对学习率周期的重新设计，是其与早期估计不同的重要因素之一。
  4. 拟合正系数，检查残差与不确定性可以用对数参数化保证 A、B、E、α、β 为正，并采用稳健损失减弱异常点影响。原论文使用预测与观察的 log loss 差值的 Huber 损失；不要把“在 log 空间拟合”误解为简单地给联合公式做线性回归。
  5. 做真正的留出验证将部分更大规模或不同预算的完整实验作为留出集，而不只是随机留出同一次训练的邻近 checkpoint。使用多个种子或 bootstrap 估计不确定性，检查外推是否系统偏离。
  6. 围绕候选配置验证真实训练先用中等规模实验检验预测，再选取受数据与硬件约束的配置。不要因为模型给出小数点后三位，就认为最优参数量具有同等精度。
Kaplan 与 Chinchilla，不是“旧公式完全错了”

两者都支持规模的经验可预测性，且都不要求把每个模型训练到完全收敛。差异涉及训练长度与调度、模型尺度、拟合方法和参数口径。应比较实验设计，而不是只背 0.73 与 0.50。

F
THINK BEYOND PRETRAINING

训练最优，不等于部署最优

经典计算最优问题是：固定训练 FLOPs，最小化预训练 loss。如果模型要服务大量请求，较小模型每次推理更便宜，那么先花更多训练计算“多读一些数据”，可能降低整个使用周期的成本。

Clifecycle ≈ 6ND + 2NQ
D：训练 tokensQ：简化模型中累计推理处理的 token 数

在这个非常简化的稠密模型算式里，2NQ 对应推理前向的主要矩阵运算。当 Q 很大时，减小 N 带来的重复节省，可能超过增加 D 的一次性训练成本。

优化问题也随之改变

可以把问题改为：给定目标质量 Ltarget 与推理需求 Q，在满足 L̂(N,D) ≤ Ltarget 的前提下，最小化 6ND + 2NQ；或固定生命周期预算来优化质量。最优训练比例便不再必然是 D ≈ 20N。

这个式子不等于线上成本模型

真实系统还受 prompt 长度、prefill/decode 差异、KV cache、batch 大小、延迟目标、内存带宽、量化和并行通信影响。输入与输出 token 的实际成本并不相同。2NQ 只是解释方向的近似，不能直接作为定价或采购依据。

因此，一个小模型训练了“远超 20N”的 tokens，不自动反驳 Chinchilla；可能只是目标从训练计算最优，变成了数据受限、模型大小受限或推理成本最优。判断方案之前，先问清楚优化目标。

Beyond Chinchilla-Optimal: Accounting for Inference in Language Model Scaling Laws（Sardana et al., ICML 2024）系统讨论了将推理需求纳入资源分配的问题。

G
WHY CHINCHILLA MATTERS

突破不在“首次发现”，而在修正与验证

用本章的两个层次理解：Chinchilla 更系统地测量资源与 loss 的关系，从而改变最优预算分配的建议，再把预测落实为一次大规模训练。它的核心贡献是实验方法、资源配比与实际验证，而不是一种全新的模型架构。

1. 相比前作：预算最优问题早已存在

Kaplan et al.（2020） 已研究规模幂律、样本效率与固定预算下的最优配置。其建议更偏向扩大模型、用相对较少的数据，并在充分收敛前停止训练。

Chinchilla 同样不要求把每个模型训练到充分收敛。修正的是模型该多大，以及应该训练多少 token 再停止，不是从“提前停止”改成“必须收敛”。

训练预算增加 10 倍时，最优资源规模如何扩展
工作参数量 N训练 tokens D
Kaplan 2020约 ×5.4约 ×1.9
Chinchilla 2022（概括）约 ×3.2约 ×3.2

“大致同步扩展”说的是增长指数接近，不是各分一半 FLOPs；训练计算量近似为两者的乘积 6ND。当时不少模型扩大参数量，却仍只训练约 300B tokens。Chinchilla 指出：相对于已有预算，它们往往模型偏大、训练量偏少。

2. 为什么结论变了：实验设计更贴合问题

论文进行了超过 400 次模型训练，覆盖约 70M 到超过 16B 参数及多种训练长度，不只比较模型大小，还系统改变处理的 token 数。

关键细节：学习率调度应匹配目标训练长度

举例说，专门为 100B tokens 设计并完成学习率衰减的训练，不等于计划训练 1T tokens、只取其中 100B 时的 checkpoint。后者尚未完成适合短预算的学习率衰减，可能高估该预算下能达到的最低 loss。

Chinchilla 对这一问题做了实验并校准调度。但调度不是差异的唯一原因：模型规模范围、拟合方法以及最优曲线的弯曲程度也有影响。

它用三种方法交叉检验结论：

  1. 训练曲线包络：在多个模型与训练长度中，找每笔计算预算对应的最低 loss。
  2. IsoFLOP 曲线：固定总 FLOPs，改变模型大小与 token 数，直接寻找损失谷底。
  3. 联合损失拟合：拟合 L̂(N,D) = E + A/Nα + B/Dβ，再在预算约束下求最优解。

三种方法都支持更平衡的扩展，但具体指数与最优模型大小并不完全相同。这是相互支持的经验结果，而非精确的普适定律。

3. 为什么有说服力：按预测训练，确实更强

大规模对照：论文报告相当的训练计算预算
模型参数量训练 tokens
Gopher280B300B
Chinchilla70B1.4T

Chinchilla 只有 Gopher 四分之一的参数，却在大量下游评测中取得更好结果，同时降低模型存储需求与推理计算成本。贡献不只是“拟合曲线更合理”，而是用小规模实验指导昂贵训练，并验证了调整配比的价值。预算比较应遵循论文的 FLOPs 统计口径，不应要求表中舍入数值的 6ND 乘积严格相等。

这不是只改变 N、D 的完全纯净对照

两者还有优化器（Adam / AdamW）、tokenizer、数据采样比例及权重存储精度等差异。因此不能把全部提升都归因于资源配比，也不能据此声称已验证所有尺度上的精确最优点。

4. 应该记住什么，不该推导出什么？

重点从“参数有多大”转向给定计算预算，怎样得到更好的模型。模型规模与数据规模需要一起考虑，高质量数据的收集与使用因此更重要。

  • 不意味着小模型总比大模型强：结论依赖预算与训练条件。
  • 不意味着 20 tokens / parameter 是精确常数、数据上限或收敛标准。
  • 不意味着历史系数能保证任意新模型的最低 loss；外推与部署成本仍需单独验证。

历史定位：Kaplan 系统展示了规模可预测、预算可优化的框架；Chinchilla 对模型—数据权衡作出影响重大的实证修正，并给出大规模验证。
