2工作方式：保留这一个区别就够了

独立堆叠：h₂ = Fθ₂(Fθ₁(h₀))
共享循环：h₂ = Fθ(Fθ(h₀))

Part I · 动机，而不只是机制

最强的理由：学一个可复用的求解器，让计算预算可以增长，而不强迫知识存储同比增长。

3省显存：省的是哪一部分？

你的 KV 质疑是关键。但“大规模部署时一定由 KV 主导”也取决于上下文、并发、GQA/MLA、精度和分片方式。

对照方式权重存储计算与 KV
p 参数循环两次 vs 2p 独立深模型核心权重约减半；词嵌入等固定开销不减半。同宽、同执行深度时计算近似；朴素逐轮 KV 也近似，而非减半。
p 参数循环两次 vs p 浅模型基本不变。核心计算与逐轮 KV 增长，不能称作免费升级。
训练阶段可减少权重、梯度和优化器状态。完整展开的激活仍增长；checkpointing／截断反传另有代价。

共享 WK、WV 不等于共享每轮 K、V。对普通逐层缓存，单请求的粗略预算是 K = 2 × Lexec × T × nkv × dhead × bkv；其中 Lexec 是执行的注意力层数，不是独立权重层数。MLA、滑窗或跨层共享需要另写缓存模型。

KV 主导时，权重节省会被稀释

同 KV / 请求的情况下，省 ΔW 可多容纳约 ΔW/K 个请求。长上下文使每个请求更贵，绝对新增并发更少；KV 可用空间本来就很大时，相对收益也小。

权重的价值不止在并发

减少模型切分、让一份模型放进更少设备、降低副本成本，或跨过片上驻留门槛，可能比多放几十条 KV 更重要。反之若已算力饱和，更多可驻留请求不等于更高吞吐。

3.1 省掉的权重，最多换来多少并发？

同一个理想化显存池：Bmem = max(0, ⌊(H − W − Mreserve)/K⌋)。固定预留 16 GiB，包含运行时与安全余量；忽略碎片、分片不均和随 batch 变化的工作区。

基线固定采用 32 个执行注意力层、8 个 KV 头、头维度 128、BF16 缓存，即 128 KiB/token；默认每请求 1 GiB。权重占用独立设置，不代表某个真实模型。q 的变化是独立假设，不会自动保证质量或计算量不变。

饱和曲线仅隔离“并发边际递减”，两种模型共享曲线是刻意假设，不是预测。真实循环模型可能有不同 T∞、带宽开销与服务时间；生产应比较满足 p95 延迟约束的有效请求/秒（goodput），而不是显存容量上限。

不是“越多 batch 越好”低 batch 下，GPU 解码可能被权重搬运限制；增加 batch 可摊薄读取成本。batch 变大后，算力、KV 读取或通信先饱和，收益递减。仅让权重文件更小，若循环间仍要从 HBM 重读，并不保证权重流量按同样比例下降。

3.2Cerebras：硬件协同设计是合理假说

这个猜测很有解释力，但目前只能作为工程推断。据 Cerebras 2024 年的推理系统介绍，WSE-3 单片集成 44 GB SRAM，超出容量的模型按层映射到多台 CS-3。这里是晶圆级计算与片上存储紧耦合，不宜直接等同于在存储阵列内做乘加的 compute-in-memory。

这更像以计算换静态参数存储的增长，不是“只 scale 计算、完全不 scale 存储”：KV、激活、状态搬运、串行时延和功耗仍要付费。在片上容量门槛附近，收益可能是非线性的；但循环若反复占用同一片计算资源，也可能不如独立层流水线有吞吐优势。

4学习效率：更像“结构约束”，不是“多看一遍数据”

参数 p 循环两次，在同样 token 数后能胜过 2p 的独立深模型吗？可以在某些任务上胜出；不构成通用优势。

有理论与实验支持

迭代式归纳偏置

关系传播、逐步更新候选解、重复应用规则，不一定需要每步一套新权重。共享迫使不同深度协作学习通用更新规则，也可能抑制逐层过拟合，提高有限数据下的泛化。

不能直接推出

“一个参数得到两倍训练”

共享权重会汇总不同调用位置的梯度，但它们来自同一批样本，相关且可能冲突。一次反向传播通常仍只对应一次优化器更新，不是自动增加独立样本量。

梯度汇总为什么不等于两份独立监督。在结构、宽度和接口一致时，独立深网络可以令对应层权重相等来表示共享模型，因此共享的优势不是函数类更大；更合理的来源是归纳偏置、优化路径与泛化。代价是更小的自由度与逐层专门化能力。

同数据量也不是唯一公平标准：p 循环两次和 2p 单次的主干计算可近似匹配，但 p 浅模型通常能用相同算力训练更多 token。要判断“效率”，还应比较等训练 FLOPs、等数据质量和等部署延迟的最优模型。

另一项重要动机是可调测试时计算：针对难输入分配更多内部步骤，而不新加载一个大模型。前提是训练过相应深度分布或路由器；不是给任意已训练模型加循环就生效。训练方法 · 何时停止

补充动机：历史检索，不等于持续更新状态Google DeepMind 的 The Topological Trouble With Transformers（2026）讨论了固定深度前馈结构对动态状态跟踪的限制：已在深层算出的状态，不能直接反馈给后续输入的浅层。它也提醒我们，增加深度循环预算，不等于获得跨时间持续递推的状态。论文解读：限制、例外与两种循环的区别

5商业壁垒：减少可学信号，不是让能力不可蒸馏

“有防蒸馏激励”是合理商业推断；“闭源优势必须靠杜绝蒸馏”不是已成立的必然条件。

学生能拿到什么如果更多推理移入潜在状态仍然存在的学习路径
明文中间步骤可用过程监督可能变少，难题的信用分配可能更难。教师仍可生成解释或合成解题数据，但未必忠实对应内部过程。
最终答案只要接口输出答案，这部分行为信号仍存在。答案监督、序列级蒸馏、筛选高质量样本；效果取决于覆盖度和学生能力。
输出概率 / logits只有接口允许访问才存在，不能默认开放。经典软目标蒸馏不要求学生复制教师的隐藏轨迹或架构。

不可见的计算过程 ≠ 不可迁移的输入输出行为。另一方面，不能保证小学生只靠答案就能高效吸收长程算法：潜在步骤少了过程监督，且学生本身可能需要足够的展开深度。增加复现难度是可能的，获得架构层面的“防蒸馏保证”则没有依据。

两条关键反例

不使用 loop 的服务也能隐藏内部文本 CoT；使用 loop 的模型也能输出长 CoT。因此，“不展示推理”不是循环架构独有的商业壁垒。

把潜在循环与文本 CoT、工具交互结合，可能比彻底替代更实用。过程可读性下降还会增加调试、审计和监控成本，不能只算防模仿收益。

概念依据：Hinton et al., Distilling the Knowledge in a Neural Network（2015）。它支持输出分布蒸馏的概念，不是“当代闭源 latent LLM 已被低成本完整蒸馏”的实证。

7Open problems：哪些实验最值得做？

有进展不等于问题已解决。下面每一项都应落到可比较的指标，而不是只看“多循环会变强”。

01 · 标度律

参数、数据与循环如何联合分配？

固定训练预算时，扩大宽度、增加独立层、增加 loop 或多训练数据，何者处于最优前沿？SMELT 是特定 MoE 族的证据；数据受限、过训练与前沿尺度仍待检验。

要测：等数据／等算力的双重对照，分别报告困惑度、知识与推理。

02 · 优化与外推

怎样避免“多算但不进步”？

梯度冲突、状态坍缩、振荡、忽略循环输入，都会破坏迭代。训练 R 轮后测试 2R 轮能否继续获益？更进一步，怎样结合深度循环与跨时间状态反馈，让模型持续更新状态，而不只是扩大一次预测的深度预算？

要测：跨深度质量、多种子、状态更新链的长度外推与长期一致性。

03 · 停机决策

什么时候再算一轮值得？

变化小不等于正确，不确定性高也不保证可通过循环解决。路由必须兼顾难度估计、预算约束和校准，避免只选择最容易的 token。

要测：质量—延迟前沿、难例退出失误、分布外输入。

04 · KV 与调度

容量节省能转化为服务收益吗？

跨轮 KV 复用是否损伤质量？早退 token 缺少深层 KV 怎么补？异构深度 batch、流水线、片上驻留与通信如何共同优化？

要测：prefill/decode 一致性、峰值显存、能耗、p95 延迟下的 goodput。

05 · 与 CoT 协同

哪些中间状态应该变成文本？

潜在循环擅长内部变换，文本能充当可保存、可检查的外部草稿，工具交互仍需离散动作。如何动态选择潜在步、文本步与工具调用？

要测：相同总推理 FLOPs，而非相同可见输出 token 数。

06 · 蒸馏与可观察性

A1 / STATE UPDATE

把参数和状态分开看。

最简的深度循环可以写成反复应用同一函数。Huginn 的设计更具体：每轮同时输入原始上下文的编码与上一轮状态。

HUGINN 宏观设计 · 论文 v2 §3.1
e = P(x)
s0 ∼ N(0, σ²I)
sr+1 = Fθ(sr, e),   r = 0, …, R − 1
p = C(sR)

这是宏观公式。论文实际大模型的初始化使用截断正态分布；具体归一化、尺度与采样细节见 §3.2、§4.1。

x
输入 token 序列。
P / e
前置模块（Prelude）及其输出；e 为整段序列的输入表示。
sr
第 r 轮隐藏状态；整序列形式为 n × d 矩阵，不只是一枚 token 的向量。
Fθ
带共享参数 θ 的循环核心，可包含多层因果自注意力与 MLP。
R
本次采用的循环次数；不等于参数副本数。
C / p
输出模块（Coda）及预测分布；包括输出层与词表投影等步骤。

为什么每次都送入 e？

把更新规则理解成“依据题目 e 修正当前解 s”。如果题目只在初始化时出现，反复更新可能丢失条件信息。Huginn 在每轮将状态与 e 拼接，再通过可学习 adapter 映射回隐藏维度，使原始输入始终可达。

这是一种稳定迭代的设计选择，不是数学上对所有 looped 模型的统一要求。其他实现可能采用加法注入、不同初始状态、步数嵌入或部分参数共享；有效性都需要单独验证。

权重不动

推理时的 θ 通常固定。变化的是 sr；所以这不是“在测试时对权重做梯度更新”。这一区别与循环是否提高准确率、是否节省显存是独立问题；主页面的交互专门估算部署容量，而不模拟真实模型推理。

原文：Recurrent Depth §3：架构与训练目标 ↗

A2 / TWO AXES

token 往前走，状态向深处走。

序列轴 t

自回归生成

在已有前缀上预测下一个 token，将 token 加到上下文，再预测后续 token。文本 CoT 主要通过增加中间 token 延长这条轴。

深度轴 r

核心重复计算

在一次 token 预测内部，把状态交给同一循环核心若干次。在这种设计中，增加轮次不要求新增文本或潜在 token 位置。

两者可以组合：对生成的每个 token 都运行多轮循环，也可以用一个循环模型生成较长的文本思维链。循环 Transformer 并不天然取消自回归，也不禁止 CoT。

训练 / prefill 能并行，循环依然有依赖

在完整序列训练或 prefill 中，同一轮的多个位置通常可以一起计算，但仍受因果掩码约束，不能看到未来 token。第 r + 1 轮依赖第 r 轮，因此这些深度步骤不能全部同时执行。解码时，序列轴上也通常要等前一个 token 生成完成。

默认的 Huginn 宏观公式重新初始化 s0；将上一 token 的最终状态用作下一 token 的初始状态，是论文 §6.3 额外探索的连续思维策略，不能把它误写成所有深度循环的默认行为。

A3 / TRAINING

模型得学会“反复做也有用”。

普通模型的不同层通常已经各自专门化。把任意已训练层复制调用多次，并不保证它们组成稳定、有益的迭代系统。共享循环最好从训练目标、深度采样、归一化和初始化一起设计；改造现有模型也通常需要针对性训练与验证。

随机循环深度的语言建模目标
L(θ) = Ex,R [ − ∑t log pθ(xt+1 | x≤t; R) ]

这里用 θ 简记模型的全部可训练参数，R 从训练深度分布中采样。优化目标仍可以是下一 token 预测，并不要求每一轮都有人工标注的中间推理步骤。

  1. 在不同深度上训练。Huginn 用 log-normal Poisson 分布随机采样轮数，覆盖较浅和偶尔更深的展开。工程上每个 micro-batch 统一深度，并在并行 worker 间同步，减少等待。
  2. 控制反向图长度。主实验只对最后最多 8 轮循环做反向传播，前面的轮次仍做前向。截断降低激活保存与反向计算，但前向成本仍随 R 增加。
  3. 维持输入与状态信号。输入注入、归一化顺序和初始化尺度非常重要。论文记录了 token 表示坍缩，以及模型忽略传入状态、增加轮次也不改善的失败案例。
  4. 检查真实的多深度表现。只看训练损失不够，还应看不同轮次的验证损失与目标任务指标，确认模型没有学成“循环一次和很多次都一样”。
不是免费训练

共享权重降低参数与优化器状态存储；未截断时，跨轮激活和反向传播图仍会增长。截断反传改变了梯度估计，不能等同于完整展开的精确梯度。即使只对最后几轮反传，输入 e 在这些轮次的注入仍可给 Prelude 传递梯度。

原文：§3.3 训练目标与截断反传；§4 训练设置与失败尝试。

A3.1 / SHARED GRADIENTS

同一参数用两次，训练信号就翻倍了吗？

先把两次调用写成独立参数 θ₁、θ₂，令 J(θ₁, θ₂) 为展开图的样本损失。共享模型相当于施加 θ₁ = θ₂ = θ：

∇θ J(θ, θ) = [∂J/∂θ₁ + ∂J/∂θ₂]θ₁=θ₂=θ

每个位置的偏导已经包含经后续状态传播的链式项；不要再把这些梯度当作两份独立样本相加计数。完整反传如此，截断反传则会舍弃部分路径。

  • 可能互补：不同深度的状态分布提供不同的学习需求，推动模型学会跨阶段可复用的规则。
  • 可能冲突：浅层需要提取表示，深层需要组合或校正；共享参数必须在相互不一致的梯度之间折中。
  • 不增加独立样本：训练 token 数、样本数、优化器更新次数不会因为调用两次就自动翻倍，计算量却真实增加。

若架构接口和宽度相同，独立深网络可以把对应权重设成相等，因而包含共享模型的函数类。共享更可能通过降低自由度、正则化和优化路径改善有限数据下的泛化；这不与“较大函数类有更强表示能力”矛盾，也不保证所有任务都受益。

公平对照至少应覆盖：① 相同 token、同顺序、近似同 FLOPs 的共享／独立深模型；② 相同参数的浅模型；③ 相同总训练算力下，让浅模型使用更多数据的配置。多随机种子和各自合理调参可避免把超参数适配误判成架构优势。

A4 / ADAPTIVE COMPUTE

停止条件，是另一项设计。

“可以重复执行”与“知道何时该停”不是同一能力。固定预算最简单：所有 token 都运行 R 次。自适应预算则可能根据位置、输入或中间状态决定退出时间。

常见的停止策略及其限制
策略怎么停主要问题
固定 R达到预设轮数易部署，但简单 token 也支付相同循环成本。
状态变化阈值检查相邻状态的相对差异表示可能振荡或稳定在错误答案；不同尺度需校准。
输出分布变化比较相邻轮次预测分布的差异需额外运行输出模块；低差异不保证预测正确。
学习停止机制训练 halting / routing 决策需要相应训练与预算约束；动态 batch 调度更复杂。

Huginn §6.1 展示了相邻步预测分布的 KL 差异低于阈值后退出的实验；Universal Transformer 则探索过 ACT 逐位置动态停机。两者不是一套完全相同的停止算法。

为什么“再多算一点”可能无效？

迭代可能已经饱和，也可能进入周期或偏离有用状态；超过训练分布的深度还会发生分布偏移。真实潜在轨迹不必单调接近某个固定点。部署时应设最大轮数，并测量质量—延迟曲线，而不是假设无限循环必然提高正确率。

原文：Recurrent Depth §6.1、§7 潜在轨迹；Universal Transformers。

A5 / OBJECTIVES MATTER

都有迭代，不代表同一种模型。

与扩散模型的区别

扩散模型通常围绕加噪、去噪或相应生成过程构建目标。Huginn 的循环核心则用语言建模损失学习状态更新；随机初始状态不自动等于扩散噪声过程。

与 DEQ 的区别

深度平衡模型通常围绕固定点求解与隐式求导构建训练。有限次数显式展开、再截断反传的循环网络，不必求出固定点，也不必使用隐式梯度。

“循环”只描述结构或计算方式的一部分。模型到底学什么，还要看目标函数、状态含义、训练方法与生成过程。

A6 / KV CACHE

共享投影矩阵，不等于共享投影结果。

同一核心层，不同轮次的状态
Kr = HrWK,   Vr = HrWV
Hr ≠ Hr+1   ⇒   K、V 通常也不同

H 表示送入该注意力层投影的表示，省略归一化、位置编码等细节。共享 WK、WV 不要求不同 H 的输出相同；不同输入也可能碰巧映射为相同结果，因此这里说“通常”。

固定轮数下的朴素实现

对每个核心层、每轮迭代保存对应的历史 token K/V。新 token 在相同轮次使用历史位置的对应缓存；这保留了固定展开图的计算语义，但缓存通常随 R 增长。

逐 token 早退为什么更复杂？

假设前一个 token 在第 4 轮停止，当前 token 却要计算到第 12 轮，那么前一个 token 第 5–12 轮的缓存根本不存在。补算这些状态会增加成本；使用最近可用的深层缓存则改变了计算路径。

Huginn §6.1–6.2 研究了两种实用策略：缺少轮次时读取已有的最深缓存；或者设定有限缓存预算，用循环槽覆写较早轮次。论文在特定评测中报告了可行性，不是证明所有模型、任务或预算下无损。

工程边界

需区分“不同轮次缓存可以近似复用”与“不同轮次 K/V 数值完全相同”。任何共享策略都必须保持因果可见性，并检查 prefill 与逐 token decode 的一致性。不能让早期位置看到未来 token。

原文：§6.1：早退与缺失缓存、§6.2：循环缓存共享。

A7 / BUDGET

至少分开记四本账。

简化成本模型：核心含 k 层，循环 R 次，前后非循环部分为固定开销
资源简化关系需要注意
参数存储Ptotal = Pfixed + Pcore共享参数不随 R 复制；不同 k、宽度与词表会改变参数量。
前向计算C(R) ≈ Cfixed + R × Ccore在序列长度等配置固定时估计；不能直接当作实际墙钟延迟。
激活存储完整反向图通常随展开深度增长checkpointing、截断反传可改变时间—内存权衡。
KV Cache朴素核心缓存 ∝ R × k × T × dkv还需乘 batch、K/V 两份与每元素字节数；此处略去非循环部分。

T 是缓存序列长度；dkv 是每层所有 KV 头的总维度。GQA/MQA、缓存量化与共享策略都会改变内存常数或增长方式。因此不能仅凭“参数量较小”就判断循环模型部署便宜。

评估一个循环模型时，至少问这些问题

  • 是在比较相同参数、相同训练 FLOPs，还是相同推理延迟？这些基线不等价。
  • 增大 R 后，目标任务提升多少？简单任务是否很快饱和？
  • 计入输出头、停止检测和缓存处理成本后，端到端首 token 延迟与吞吐如何？
  • 逐位置自适应计算能否真正节省 GPU 时间，还是被 batch 中最长任务拖住？
  • 缓存共享和深度外推是否经过独立质量评测，而不仅是少量案例？

显存容量怎样换算成并发？

把所有量放到同一个部署池中计量。设 H 为总可用显存，O 为运行时预留，W 为独立深模型权重，αW 为循环权重，K 为基线单请求缓存，qK 为循环缓存。忽略碎片和分片不均时：

B₁ = max(0, ⌊(H − O − W) / K⌋)
B₂ = max(0, ⌊(H − O − αW) / (qK)⌋)

仅在两者可部署、忽略取整时，B₂/B₁ ≈ (H − O − αW) / [q(H − O − W)]。当 q = 1，新增容量约为 (1 − α)W/K，相对增幅约为 (1 − α)W/(H − O − W)。

这揭示了两个不同效应：上下文增长使 K 变大，绝对新增并发下降，但在 q = 1 且忽略取整时，相对容量增幅不因此改变；如果权重只占总预算很小一部分，则相对增幅本来就小。不要把“KV 主导”简单改写成“省参数毫无价值”。

主页面默认 H = 160 GiB、O = 16 GiB、W = 96 GiB、α = 0.5、K = 1 GiB、q = 1，得到 48 → 96。若 K = 4 GiB，则是 12 → 24；若 q = 2 且 K = 1 GiB，则是 48 → 48。跨设备池还必须逐设备检查驻留瓶颈，不能把所有显存无损相加。

容量并发不等于有效吞吐

主页面用 T(B)/T∞ = B/(B+Bₛ) 仅示意批处理收益递减：默认 Bₛ = 32 时，48 → 96 只把同一假设曲线上的吞吐从 60% 推到 75%。两种架构实际并不一定共用 T∞ 或 Bₛ；增加循环、缓存读取与动态调度都能改变它们。

生产上应测目标请求分布、prompt / output 长度、p95 首 token 延迟和逐 token 延迟约束下的 goodput。更多并发还可能只是让更多请求占住服务资源或排队，而非提升单位时间完成数。

A7.1 / HARDWARE CODESIGN

“只扩计算、不扩参数”何时值得？

Cerebras 2024-08-27 的官方介绍给出 WSE-3 单片 44 GB SRAM，并说明超过单片容量的模型按层映射到多个 CS-3。该厂商规格是十进制 GB；主页面估算使用二进制 GiB，二者不要混算。片上 SRAM 加计算单元也不等于存储阵列内乘加。

假说需要验证可能的反作用
小核心更易片上驻留权重 + KV + 激活 + 缓冲能否同时满足片上容量、布局与带宽约束。不能只用参数数 × 精度推断能否放下一份完整服务实例。
减少权重搬运同一核心在两轮之间是否真能驻留；需量测实际字节流量。GPU 上大核心可能每轮重读 HBM，存储副本减少不等于流量减少。
减少跨设备切分循环后能否少用设备或减少边界通信，并比较相同质量。独立层流水线可承载不同请求；循环重入也会引入争用和负载不均。
利用富余算力额外循环是否落在容量／带宽受限而算力有余的区间。计算不会自动免费；串行关键路径、KV 访存和能耗仍可能增长。

这是一套可检验的设计逻辑，不是 Cerebras 或 OpenAI 已按此设计某模型的事实。要证明 codesign 优势，至少同时报告质量、设备数、峰值内存、真实吞吐、时延和能耗，并与适配相同硬件的独立层基线比较。

“思考更久、答案更短”为什么不够？

内部文本推理、工具调用、搜索、采样策略、服务端调度、结果筛选以及界面摘要，都可能改变可见文本和延迟。多个不同系统可以产生相似外部表现，因此仅靠黑盒交互无法唯一识别内部架构。

同样，潜在状态不可直接阅读不意味着“没有推理”，但也不能凭“内部有连续向量”就认定发生了某种具体推理算法。自然语言解释与内部计算的忠实对应关系，本来就需要单独研究。

B4 / COCONUT

都在潜在空间思考，循环位置不同。

Coconut 将语言模型的末层隐藏状态直接作为下一连续思维位置的输入嵌入，避免先将该状态投影、采样成一个文字 token。模型继续运行，直到切回语言模式输出文本。

HUGINN 式深度循环

在核心块内增加步骤

重复调用模型中间的一组共享层，处理相同序列位置上的状态。增加深度轮次本身不增加序列位置。

COCONUT 式连续思维

用隐藏状态接续推理位置

把整个语言模型的输出状态反馈为下一个输入嵌入。普通模型内部不同层可以仍有独立权重，连续思维位置也会带来缓存开销。

因此二者有家族相似性，却不应混用具体公式、训练配方和成本结论。尤其不能把“没有额外的可读文字”直接等同于“没有额外序列位置或 KV Cache”。原则上，连续思维的反馈方式也能与内部共享循环块组合。

依据：Coconut 论文；关于两类路线联系，亦见 Recurrent Depth §6.3。本文是结构层面的比较，不声称有直接的公平性能对照。

B4.1 / STATE TRACKING & TOPOLOGY

前馈结构的拓扑限制：为什么“再算几轮”还不够？

The Topological Trouble With Transformers，Michael C. Mozer、Shoaib Ahmed Siddiqui、Rosanne Liu，Google DeepMind。首次提交于 2026-04-18；以下解读固定依据 v2（2026-04-28），不声称覆盖后续所有修订。这是一篇围绕架构限制的概念分析与文献综合，不是新的循环模型基准成绩报告。

1. 保存历史，不等于持续维护状态

st = f(st−1, xt)

t 是输入时间步；s 是读入新信息后更新的状态，不是历史 token 的简单集合。比如对话中实体的当前关系，需要依据新事件继续更新，而不只是找回某句话。

论文 §2 指出，标准因果 Transformer 的信息沿层级向上流动。若上一个位置的状态在深层形成，后续位置的浅层不能直接读取它；要依赖它继续更新，就需要沿更深的路径计算。对于无法由更浅算法替代的串行更新链，固定有效深度成为限制。问题既包括深度最终耗尽，也包括状态形成得太晚，无法及时参与浅层处理。

2. 深度循环与时间循环，解决的问题不同

依据论文 §3；关键不在是否重复运行，而在状态沿哪条轴传播
计算方式增加了什么能力仍需付出的代价或限制
深度循环重复共享层，增加处理当前上下文的有效深度。固定 R 只扩大有限深度预算；不会自动把最终状态交给下一输入步。R 随任务增长可增加可处理的依赖深度，也会增加计算。
跨时间／块级循环将处理上一输入步或上一块后形成的状态，传给下一步或下一块。一般状态更新带来串行依赖；训练并行度、跨步信用分配与长期稳定性仍是问题。
文本 CoT／潜在反馈把深层结果变成后续输入，使结果能重新进入浅层。需要额外计算与可能的序列位置／缓存；潜在思考能否持续跟踪状态，取决于具体反馈路径，不能一概而论。

因此，“自回归逐 token 生成”“在单次预测内部循环”和“跨输入传递潜在状态”不是同一个概念。主页面介绍的深度循环可以与时间循环结合，但参数共享本身并不保证存在跨时间的状态反馈。

3. 不要把论点扩大成普遍不可能性

  • 不是 L 层只能处理 L 个 token。某些更新可以合并、并行计算，或通过历史回查、状态分解绕过逐步更新。论文讨论了部分任务可用随长度增长的 O(log n) 深度解决。
  • 长上下文与状态递推解决不同问题。更多历史可访问，不会凭空增加串行计算路径；但能从历史直接算出答案的任务可能受益。
  • 案例失败不是拓扑因果证明。对话错误还受训练与优化影响；可表示性、能否学到、实际运行成本也应分别评估。
  • 循环不是可靠性的保证。跨时间反馈支持状态传递，但仍可能遗忘、累积误差或训练不稳定。可并行的特殊状态更新也不等于完全没有状态能力。
对本专题的补充除了省权重与提升参数效率，循环还涉及“计算图是否适合持续更新状态”。这篇文章支持认真研究反馈路径，却不构成对所有 depth-loop 架构的统一背书，更不能据此认定某个闭源模型的实现。

4. 开放问题：怎样把两种循环结合起来？

下面是据此提出的评测建议，而非论文已验证的结果：在等训练／推理预算下，比较固定深度、可变深度循环、跨时间状态反馈和文本草稿；逐步增加状态更新链长度，测量长期一致性、长度外推、缓存增长、延迟与训练并行效率。重点是分辨“只是多算了几层”与“真正利用了可持续更新的状态”。

B5 / DISTILLATION

“降低可蒸馏性”应该是一个实验命题

Hinton、Vinyals、Dean（2015）的知识蒸馏提供一个概念反例：学习教师输出分布，不需要读取教师的隐藏轨迹，也不要求学生同构。但这类软目标需要概率分布；如果 API 只返回文本，能做的是答案／序列监督，信息量不能混同。

Lsoft = − Ex ∑y pT(y | x) log pS(y | x)

这是输出分布蒸馏的标准概念式，非本次摘要页逐字公式。教师固定时，相当于最小化教师到学生的 KL 散度（差一个与学生无关的项）；不要求对教师反传。只拿到答案时，可用其作为目标序列，但不再是已知完整分布的监督。

因而“没有可读过程”不能推出“输出行为原则上不可迁移”。但也不能走向另一个极端：学生能否在有限数据和计算下学会长程算法，受输入覆盖、监督信息量、容量、可用深度和优化难度制约；训练分布内模仿成功也不保证分布外算法泛化。

一个更有说服力的对照设计

  1. 固定教师质量与查询集合：比较答案-only、答案 + 文字过程、允许时的 logits、可访问时的潜在轨迹。后两者不是一般闭源 API 的默认权限。
  2. 按完整成本匹配：记录教师总计算／查询费用、监督 token 数，以及学生的训练 token 和 FLOPs；相同查询次数不一定等成本。
  3. 比较多种学生：浅模型、独立深模型、循环模型；避免让缺乏足够计算深度的学生承担所有结果。
  4. 评测算法与泛化：在未见任务长度、组合深度和新分布上测试，区分记住答案模式与学会求解器。
  5. 加入产品控制组：普通 Transformer 隐藏内部 CoT，循环模型仍输出 CoT。由此区分架构效应与接口开放程度。
目前只能给出的结论减少可观察的过程监督可能提高模仿门槛；没有证据支持 looped 架构自带“无法有效蒸馏”的保证，也没有证据证明它是 OpenAI 采用该路线的商业原因。闭源竞争力也可能来自数据、训练成本、产品集成、分发和服务质量，不必把阻断蒸馏设为唯一必要条件。

B6 / EVALUATION CHECKLIST

读到“更高效”，先问五件事

到底匹配了什么预算？

参数、token、训练 FLOPs、推理 FLOPs、延迟和 KV 不能互相代替。最好同时给同数据与同算力两套结果。

提升的是哪类能力？

分别看困惑度、闭卷知识、开卷任务与多步推理；均值可能掩盖子任务退步。

参数更少，有没有真正减少总显存？

报告权重、优化器、激活、KV 与运行时占用，不把共享权重推断成共享缓存。

省算术是否变成真实系统收益？

在指定硬件与请求长度分布下测量吞吐、尾延迟、能耗；容量上限不是可交付的并发 SLA。

因果证据还是一种合理解释？

公开方法有效不代表某产品采用；CoT 更短不代表 looping 所致；难以读取轨迹也不代表难以学习输出行为。
