“循环深度是一条值得研究的路线”与“某个闭源模型采用它”是两个独立命题。前者可以读论文、看代码；后者需要针对该模型的直接证据。

B1 / CLAIMS & EVIDENCE

关于 OpenAI 的传闻，能说到哪一步？

本专题的结论

本次检索看到了关于 OpenAI 前沿模型使用 recurrent depth / looped transformer 的媒体转述，但未取得足以核验该架构归属的一手技术披露。这表示证据不足，不等于证明其没有采用。本文不为任何具体闭源模型补写参数量、循环次数或缓存实现。

2026 年 9 月讨论的可追溯来源
  • The Information：Secret Technique Behind OpenAI’s Astra Model Sparks Security Concerns。本次请求返回 403，未读取全文；“采用 recurrent depth 并影响推理可见性”的说法按下列评论转述记录，不视为独立核验。
  • Raschka，2026-09-02：OpenAI Astra and Looped Transformers。技术评论，解释层复用不必抑制可见 CoT；不是 OpenAI 的架构披露。
  • Raschka，2026-09-09：GPT-6 Astra, Looped Transformers, and Hidden Reasoning。转引 Jakub Pachocki 关于当前模型计算图深度与 GPT-4 接近（约两倍以内）、可监控性趋势不依赖架构变化的回应。本次未独立取得原帖，因此仅作为转引记录。

计算图深度接近既不能确认，也不能排除参数共享；“存在监控退步”与“由 looping 导致”又是不同命题。这里不裁定某模型的未公开实现，也不推断其商业动机。

多个转述若都来自同一条消息，不能算成多个独立证据。搜索摘要和产品名称也不能替代技术披露。合作公告只能支持算力合作，不能确认 looped 架构：OpenAI / Cerebras 公告本次仅取得官方搜索摘要，正文返回 403。

哪些材料能支持“某模型采用某架构”
材料能支持什么不能直接推出什么
官方技术报告 / 代码在明确的模型与版本范围内，支持其披露的结构。未披露的训练配方、实现细节、其他版本也完全相同。
公开研究论文证明作者研究了某种方法，并报告相应结果。同领域的某家公司的产品已经采用它。
媒体报道 / 二手转述作为待核验线索，需追溯原始出处与上下文。完整且已确认的架构事实。
输出与速度变化观察到产品行为、性能或延迟变化。变化唯一来自 looped transformer。

“思考更久、答案更短”为什么不够？

内部文本推理、工具调用、搜索、采样策略、服务端调度、结果筛选以及界面摘要，都可能改变可见文本和延迟。多个不同系统可以产生相似外部表现，因此仅靠黑盒交互无法唯一识别内部架构。

同样，潜在状态不可直接阅读不意味着“没有推理”，但也不能凭“内部有连续向量”就认定发生了某种具体推理算法。自然语言解释与内部计算的忠实对应关系，本来就需要单独研究。

更新原则

如果未来出现正式披露，应记录原始链接、模型版本、发表日期和原文范围，再更新归因；不要把未经确认的猜测反写成早已确定的事实。

B2 / READING RESULTS

Huginn 证明了什么，没有证明什么？

Geiping 等人的论文展示了一个 3.5B 参数的循环深度语言模型。公开数据、训练代码与模型，让这条路线不只停留在示意图上。以下数字固定引用 arXiv v2，2025-02-17，避免混用版本或不同 checkpoint。

原文支持

一条可行的研究路线

在该模型与所测任务中，增加循环次数可以改善推理表现；不同任务的收益与饱和点不同。论文还探索了自适应退出、缓存共享和状态热启动。

不能外推

不是闭源前沿模型的拆解

不证明 OpenAI 使用相同实现，不证明循环必胜同计算预算模型，也不证明增加 R 能一直改善表现或无损替代知识容量。

三个很容易混淆的数字

  • 3.5B：独立参数量，不随推理循环次数复制。
  • 约 800B tokens：预训练数据处理量；论文训练日志写实际完成 795B，概述取约数。
  • “50B-equivalent compute”：指测试时计算负载的量级类比，不是 50B 个独立参数，也不是质量达到了所有 50B 模型的水平。

论文还明确讨论了数据混合、学习率未冷却、训练规模等限制。与其他模型比较时，参数量、数据量和计算量并非同时匹配。某个 3.5B 循环模型优于较老基线，不足以证明在当代等训练预算、等延迟的比较下必然更优。

建议连读：§5 基准结果与局限、§6 探索性推理策略，不要只看摘要中的最大数字。

B2.1 / MATCHED DATA

p 循环两次 vs 独立 2p：应该怎样读？

依据 Reasoning with Latent Thoughts v1，§3.1、表 3、附录 A.2：12 层循环两次与独立 24 层使用同一批 250B Pile tokens，顺序一致。宽度等其他超参数保持一致，论文以主干层预算比较 FLOPs。精确总参数量不等于严格的 p / 2p，因为含词嵌入等固定开销。

主页面的原表摘录中，循环模型的数学任务均分 34.3 高于 29.3，但困惑度 7.90 差于 7.40，闭卷 QA 为 9.3 对 11.2。结论是任务依赖的归纳偏置，而非普遍更好的语言建模。

容易误读之处原始口径与限制
“推理任务全部更好”数学 MultiArith：循环 2.0，独立深模型 2.7。推理基础任务中的 Code depth-1 为 21.3 对 24.2；组均值优势主要来自 depth-0 查询。见附录表 7–8。
“总均分代表所有实验”表 3 的 All Tasks 只含闭卷、开卷与数学共 15 项，不包含另外 4 项推理基础任务。
“7.90 是交叉熵 loss”这是 perplexity，不是 loss。二者相关但不能直接混用数值。
“p 是精确的某个 B 数”正文与附录对 24 层基线的规模称呼存在 1B / 1.5B 差异。本专题采用可核查的 12 / 24 层结构，不自行推算精确总参数。
“证明测试时临时加循环就变强”这些配置分别训练，不是对同一 checkpoint 随意增加 R 的实验。Huginn 的可变深度测试回答的是另一个问题。
“均分更高已统计显著”主表未报告多种子均值与置信区间，也没有证明在前沿尺度、等部署时延下普遍成立。

独立网络可以用相等权重表示共享网络，故此实验不是“共享扩大了函数类”。更合理的解释是共享约束影响有限数据下的泛化与优化；它同时降低知识存储和各层专门化的自由度。

B2.2 / THREE MATCHED BUDGETS

SMELT：不把额外计算误认成架构收益

依据 SMELT v3（2026-09-11），§3–4。中间一半层执行两遍，有效深度约为 1.5 倍；循环区残差更新缩放为 1/2。它不是只改变一个 loop 开关，而是联合调节宽度、专家数和注意力配置。

匹配预算如何补偿循环开销论文报告的典型差异
每 token 训练 FLOPs主要缩小隐藏维度；计入 attention 成本，而非只用 6N 近似。< 4%
总非嵌入参数增大专家总数，保持 top-8 路由，恢复存储容量。< 1%
KV Cache调小 head 维度、提高 GQA 比率；第二遍仍重新计算 Q/K/V。< 4%

配对模型使用相同 token 序列。训练上下文为 4096，采用文档段级 mask；最长路径约 215B tokens。四种规模中最大 54B 非嵌入参数；规模标签 100M / 200M / 600M / 1.6B 指基线活跃非嵌入参数，不是所有存储参数。

例如标为 200M 的约 95% FLOPs 等效稀疏配置：基线 12 个执行层、隐藏维度 1280、192 专家；SMELT 18 个执行层、维度 1056、288 专家。总非嵌入参数为 3.87B / 3.89B，每 token 训练 FLOPs 为 1.33×10⁹ / 1.37×10⁹。可见它是近似而非逐项完全相等的控制。

6.8%–18.0% 到底是什么？

作者分别拟合两种架构的 Chinchilla 式标度律，再在固定总计算 C = F × D 下优化每 token FLOPs F 与训练 token 数 D，比较达到相同验证损失所需的计算。这与前面的“配对实验相同 token”不矛盾：拟合最优点允许两种架构各自选择 F、D。

原论文 §4 的部分点估计；括号为 95% cell-bootstrap 区间
SMELT 计算预算FLOPs 等效稀疏度同损失训练计算节省
10²⁰ FLOPs约 97%6.8% [4%, 14%]

6.8%–18.0% 是文中六个前沿拟合点的估计范围，不是每个模型都实测该幅度。每配置只训练一次，bootstrap 不充分覆盖训练种子方差；语料为内部数据。10²² FLOPs 下更大的收益属于外推，不应混入已测试结论。

Dehghani et al. 把深度递归、自注意力与逐位置自适应计算结合起来。带着“深度循环与时间循环如何不同”这个问题读；不要把文中的特定理论条件推广到所有实际模型。

B4 / COCONUT

都在潜在空间思考，循环位置不同。

Coconut 将语言模型的末层隐藏状态直接作为下一连续思维位置的输入嵌入，避免先将该状态投影、采样成一个文字 token。模型继续运行，直到切回语言模式输出文本。

HUGINN 式深度循环

在核心块内增加步骤

重复调用模型中间的一组共享层，处理相同序列位置上的状态。增加深度轮次本身不增加序列位置。

COCONUT 式连续思维

用隐藏状态接续推理位置

把整个语言模型的输出状态反馈为下一个输入嵌入。普通模型内部不同层可以仍有独立权重，连续思维位置也会带来缓存开销。

因此二者有家族相似性，却不应混用具体公式、训练配方和成本结论。尤其不能把“没有额外的可读文字”直接等同于“没有额外序列位置或 KV Cache”。原则上，连续思维的反馈方式也能与内部共享循环块组合。

依据：Coconut 论文；关于两类路线联系，亦见 Recurrent Depth §6.3。本文是结构层面的比较，不声称有直接的公平性能对照。

B4.1 / STATE TRACKING & TOPOLOGY

前馈结构的拓扑限制：为什么“再算几轮”还不够？

The Topological Trouble With Transformers，Michael C. Mozer、Shoaib Ahmed Siddiqui、Rosanne Liu，Google DeepMind。首次提交于 2026-04-18；以下解读固定依据 v2（2026-04-28），不声称覆盖后续所有修订。这是一篇围绕架构限制的概念分析与文献综合，不是新的循环模型基准成绩报告。

1. 保存历史，不等于持续维护状态

st = f(st−1, xt)

t 是输入时间步；s 是读入新信息后更新的状态，不是历史 token 的简单集合。比如对话中实体的当前关系，需要依据新事件继续更新，而不只是找回某句话。

论文 §2 指出，标准因果 Transformer 的信息沿层级向上流动。若上一个位置的状态在深层形成，后续位置的浅层不能直接读取它；要依赖它继续更新，就需要沿更深的路径计算。对于无法由更浅算法替代的串行更新链，固定有效深度成为限制。问题既包括深度最终耗尽，也包括状态形成得太晚，无法及时参与浅层处理。

2. 深度循环与时间循环，解决的问题不同

依据论文 §3；关键不在是否重复运行，而在状态沿哪条轴传播
计算方式增加了什么能力仍需付出的代价或限制
深度循环重复共享层，增加处理当前上下文的有效深度。固定 R 只扩大有限深度预算；不会自动把最终状态交给下一输入步。R 随任务增长可增加可处理的依赖深度，也会增加计算。
跨时间／块级循环将处理上一输入步或上一块后形成的状态，传给下一步或下一块。一般状态更新带来串行依赖；训练并行度、跨步信用分配与长期稳定性仍是问题。
文本 CoT／潜在反馈把深层结果变成后续输入，使结果能重新进入浅层。需要额外计算与可能的序列位置／缓存；潜在思考能否持续跟踪状态，取决于具体反馈路径，不能一概而论。

因此，“自回归逐 token 生成”“在单次预测内部循环”和“跨输入传递潜在状态”不是同一个概念。主页面介绍的深度循环可以与时间循环结合，但参数共享本身并不保证存在跨时间的状态反馈。

3. 不要把论点扩大成普遍不可能性

  • 不是 L 层只能处理 L 个 token。某些更新可以合并、并行计算，或通过历史回查、状态分解绕过逐步更新。论文讨论了部分任务可用随长度增长的 O(log n) 深度解决。
  • 长上下文与状态递推解决不同问题。更多历史可访问，不会凭空增加串行计算路径；但能从历史直接算出答案的任务可能受益。
  • 案例失败不是拓扑因果证明。对话错误还受训练与优化影响；可表示性、能否学到、实际运行成本也应分别评估。
  • 循环不是可靠性的保证。跨时间反馈支持状态传递，但仍可能遗忘、累积误差或训练不稳定。可并行的特殊状态更新也不等于完全没有状态能力。
对本专题的补充除了省权重与提升参数效率，循环还涉及“计算图是否适合持续更新状态”。这篇文章支持认真研究反馈路径，却不构成对所有 depth-loop 架构的统一背书，更不能据此认定某个闭源模型的实现。

4. 开放问题：怎样把两种循环结合起来？

下面是据此提出的评测建议，而非论文已验证的结果：在等训练／推理预算下，比较固定深度、可变深度循环、跨时间状态反馈和文本草稿；逐步增加状态更新链长度，测量长期一致性、长度外推、缓存增长、延迟与训练并行效率。重点是分辨“只是多算了几层”与“真正利用了可持续更新的状态”。

B5 / DISTILLATION

“降低可蒸馏性”应该是一个实验命题

Hinton、Vinyals、Dean（2015）的知识蒸馏提供一个概念反例：学习教师输出分布，不需要读取教师的隐藏轨迹，也不要求学生同构。但这类软目标需要概率分布；如果 API 只返回文本，能做的是答案／序列监督，信息量不能混同。

Lsoft = − Ex ∑y pT(y | x) log pS(y | x)

这是输出分布蒸馏的标准概念式，非本次摘要页逐字公式。教师固定时，相当于最小化教师到学生的 KL 散度（差一个与学生无关的项）；不要求对教师反传。只拿到答案时，可用其作为目标序列，但不再是已知完整分布的监督。

因而“没有可读过程”不能推出“输出行为原则上不可迁移”。但也不能走向另一个极端：学生能否在有限数据和计算下学会长程算法，受输入覆盖、监督信息量、容量、可用深度和优化难度制约；训练分布内模仿成功也不保证分布外算法泛化。

一个更有说服力的对照设计

  1. 固定教师质量与查询集合：比较答案-only、答案 + 文字过程、允许时的 logits、可访问时的潜在轨迹。后两者不是一般闭源 API 的默认权限。
  2. 按完整成本匹配：记录教师总计算／查询费用、监督 token 数，以及学生的训练 token 和 FLOPs；相同查询次数不一定等成本。
  3. 比较多种学生：浅模型、独立深模型、循环模型；避免让缺乏足够计算深度的学生承担所有结果。
  4. 评测算法与泛化：在未见任务长度、组合深度和新分布上测试，区分记住答案模式与学会求解器。
  5. 加入产品控制组：普通 Transformer 隐藏内部 CoT，循环模型仍输出 CoT。由此区分架构效应与接口开放程度。
目前只能给出的结论减少可观察的过程监督可能提高模仿门槛；没有证据支持 looped 架构自带“无法有效蒸馏”的保证，也没有证据证明它是 OpenAI 采用该路线的商业原因。闭源竞争力也可能来自数据、训练成本、产品集成、分发和服务质量，不必把阻断蒸馏设为唯一必要条件。

B6 / EVALUATION CHECKLIST

读到“更高效”，先问五件事

到底匹配了什么预算？

参数、token、训练 FLOPs、推理 FLOPs、延迟和 KV 不能互相代替。最好同时给同数据与同算力两套结果。

提升的是哪类能力？

分别看困惑度、闭卷知识、开卷任务与多步推理；均值可能掩盖子任务退步。

参数更少，有没有真正减少总显存？

报告权重、优化器、激活、KV 与运行时占用，不把共享权重推断成共享缓存。

省算术是否变成真实系统收益？

在指定硬件与请求长度分布下测量吞吐、尾延迟、能耗；容量上限不是可交付的并发 SLA。

因果证据还是一种合理解释？

公开方法有效不代表某产品采用；CoT 更短不代表 looping 所致；难以读取轨迹也不代表难以学习输出行为。
