DeepSeek-V4.1-Flash
把 KV Cache 压到极限的非对称 MoE

V4.1 从头训练，不是 V4 的续训。它的核心问题是：长程 Agent 的负载以输入为主两个原因：① 单轮内，工具返回（文件、日志、搜索结果）远长于模型发出的 tool call；② 跨轮次，历史每轮都要被重新读取，累计输入随轮数按平方增长。点击查看完整解释与交互计算 →，上下文要反复 prefill、存储和搬运。为此，V4.1 在架构（CED + CSA2）、缓存精度（FP4）和部署策略（SWA Bounded Replay）三个层面一起优化。后训练算法维持不变，所有投入都放在数据与环境上。

设计动机：瓶颈从「算」转向「存与搬」

经过 V3.2（DSA）和 V4（CSA/HCA）两代稀疏注意力，长序列的计算成本已经大幅下降。剩下的主要瓶颈是 KV Cache 的容量和带宽。

① Prefill 计算

Agent 每次工具调用都会把整段上下文重新送回模型有前缀缓存时，旧历史不必重算，但要从 SSD / host 内存加载回 HBM；新增的工具结果每轮都要 prefill；缓存被淘汰或前缀被改写时，就要大段重算。点击查看完整解释 →。KV 缓存未命中时，prefill 成本很高。

对策：CED，让 prompt 只经过前 20 层。

② HBM 运行时 KV

SWA 的 KV 有上界，长序列下全局 KV 占主导。它决定单卡能并发多少个请求。

对策：CSA2 跨层共享 + FP4。

③ SSD 持久化 KV

前缀复用需要把 KV 持久化。V4 中 SWA KV 占了持久化容量的近一半，但它只在几分钟内会被复用。

对策：SWA Bounded Replay + 两级缓存。

一个视角转换报告把 DeepSeek-V4 看作「以 SWA 做局部处理的主干，再叠加一个压缩的全局上下文分支」。因此 V4.1 的思路是：局部 SWA 基本不动，集中精简全局分支。全局 KV 在层间尽量共享，局部计算仍保留逐层的深度。

02Causal Encoder-Decoder（CED）

这里的 encoder 也是因果的，和 T5 那种双向 encoder 不同。CED 的直接前身是 YoCo（You Only Cache Once, 2024）。CED 完整解读40 层分成上下两半，长 prompt 只经过下面 20 层；上面 20 层的全局 KV 直接从第 20 层输出投影得到，局部 SWA 仍逐层计算并通过回放补齐。点击查看结构、公式、回放、计算量、与 YoCo 的关系和代价 →

核心公式

标准 Transformer 中，第 \(l\) 层的 KV 来自该层隐状态 \(H_l\)。CED 的 decoder 层（\(l > L/2\)）的全局 KV 直接从 encoder 最后一层的隐状态投影得到，各层使用独立的投影权重：

\[ C_l = H_{L/2}\,W^{KV}_l,\qquad Z_l = H_{L/2}\,W^{Z}_l,\qquad l > L/2 \]

\(C\) 是 KV 条目，\(Z\) 是对应的压缩权重。和 CSA2 结合后，实际只有 decoder 的第一个 Full 层（L21）执行这次投影，后续层复用结果。

全局 KV 就绪，不等于 decoder 局部状态就绪。L21 的 SWA KV 来自 encoder 输出，L22 的来自 L21 输出，依此类推。Bounded Replay 让最后 128 个位置经过 decoder，补出近似 SWA KV，并得到预测下一个 token 所需的末尾输出。为什么不精确回放约 2560 个位置？可以精确重建，但保留 encoder 输出不等于完成计算：仍要执行 decoder 的注意力与 MoE。长输入时额外开销占比不大，小增量请求中则可能占主导。点击查看状态依赖与成本对比 →

\[ \mathcal{O}(NL)\;\longrightarrow\;\mathcal{O}\!\left(\tfrac{NL}{2} + n_{\text{win}}\cdot\tfrac{L}{2}\right)\;\approx\;\mathcal{O}\!\left(\tfrac{NL}{2}\right)\quad (N\gg n_{\text{win}}) \]

03Compressed Sparse Attention 2（CSA2）

V4 使用 CSA + HCA 混合结构，V4.1 统一为纯 CSA2。CSA2 同时在三个可以相乘的维度上压缩。

条目大小

MLA 风格：所有 head 共享一个 512 维 latent（num_key_value_heads=1，head_dim=512），再加上 FP4 存储。

序列维度

每 \(m\) 个 token 压成一个条目：encoder 用 \(m=2\)，decoder 用 \(m=1\)（不压缩）。

层维度（新）

跨层共享 main KV / indexer K，并复用 Top-K 索引。KV 共享和索引复用是解耦的，可以分别配置。

三种静态分配的模式

先区分两套 KV：每个 CSA2 层的注意力同时读 全局 KV（覆盖全部历史，压缩 + 稀疏，可跨层共享）和 SWA KV（最近 128 个 token，每层私有）。下表三种模式的区别只在全局分支上，SWA 分支在所有模式下都由本层自己计算。两者的区别与配合同一个 Query 对「Top-512 个全局条目 + 128 个 SWA 条目」拼接后做一次注意力：全局分支负责远距离检索，SWA 分支保证紧邻上下文逐 token 精确可见。点击查看图示与对比表 →

模式Main KV & Indexer KTop-K 索引本层仍然计算开销
Full本层生成；indexer K 由 main KV 投影本层 indexer 全量打分全局 Q、SWA KV、indexer Q、注意力最重

Reindex 是关键多层共享同一份 KV 时，深层 query 仍然可以重新决定读哪些位置。这样既节省 KV 存储，又保留了「不同深度关注不同内容」的能力。相关工作 IndexCache 只复用索引，不省 KV；YOIO 全网络共享路由，会损失性能；HySparse 仍保留稠密层。报告指出，这些方法都没有同时覆盖三个维度。

压缩器与索引器的简化

  • 去掉重叠：V4 的 CSA 用 \(2m\) 个原始条目生成一个压缩条目，相邻条目的来源互相重叠。CSA2 改为每 \(m\) 个条目一组，互不重叠。
  • 去掉绝对位置嵌入：压缩时不再为这 \(2m\) 个条目编码绝对位置。
  • Indexer K 由 main KV 投影得到：原来从 hidden state 出发的独立压缩路径被合并，状态更少，训练效率更高。
  • 索引器配置：32 个 indexer query head，head dim 128，attention Top-K = 512。

分层稀疏索引器（Hierarchical Sparse Indexer，仅 decoder）

复用索引后，剩下的 indexer 仍要对百万 token 全量打分。V4.1 让浅层 indexer 的结果约束深层 indexer 的搜索范围，不增加任何额外状态。打分如何训练？DSA 用主注意力分布的 KL 蒸馏训练 indexer；V4.1 没有公开具体损失，不能直接视为同一配方。点击查看训练方法与证据边界 →

  1. L21（decoder 第一个 Full 层）对全部因果可见位置打分，选出本层的 Top-512。
  2. 同时针对当前 query，把位置按每 8 个分成一个 block，block 分数取块内最大值，保留最新 block 并选出最多 2048 个 block，构建候选池先划定最多 16,384 个候选位置，让后续 Reindex 层各自从中重选 Top-512。它是按 query 生成的搜索范围，不是新 KV，也不是最终注意力读取集合。点击查看构建步骤与小例子 →（最多 16,384 个候选位置，同一 query 的后续 Reindex 层共享）。
  3. 后续 Reindex 层（L25/29/33/37）只在候选池内打分，各自选 Top-512；Reuse 层沿用最近一次的 Top-512。
训练感知（training-aware）候选池约束在后训练阶段引入，训练和推理使用同样的限制。效果是：上下文从 4K 增长到 1M（256 倍）时，单 token decode FLOPs 只增加约 1/4（FLOPs 按精度加权：BF16=1、FP8=0.5、FP4=0.25）。

05FP4 Main KV Cache

格式选择

  • Main KV：E2M1，每 16 个通道配 1 个 E4M3 scale（NVFP4 的局部分组方式），省掉二级全局 scale。平均每个值约 4.5 bit。
  • Indexer Q/K：沿用 V4 的 OCP 标准 MXFP4，追求硬件兼容性，用来加速索引计算。
  • SWA KV：对量化更敏感，保留 FP8。
  • Main KV 在 attention 之前反量化，所以不需要硬件原生支持这种格式的矩阵乘。

为什么可以省掉全局 scale？

该格式能表示的最大幅值为 \(448\times 6 = 2688\)。训练得到的 RMSNorm 权重幅值最大约为 1，所以 RMSNorm 之后 512 维 latent 的 L2 范数不超过 \(\sqrt{512}\)。RoPE 保持范数不变，因此单通道绝对值不超过约 \(\sqrt{512}\approx 22.6\)。训练中实际观测到的最大值约为 10，离溢出还很远。

量化位置：RoPE 之后RoPE 部分和非 RoPE 部分使用同一格式。在 RoPE 之前量化只有边际精度收益，却会增加 decode 开销。QAT 在后训练阶段引入。和 V4 的 FP8 main KV 相比，FP4 让 HBM 和 SSD 上的存储都接近减半。

06SWA Bounded Replay 与两级缓存

回放是补算已有位置的局部状态，不是重新生成文字。SWA 的依赖逐层向前扩展，精确重建的回溯范围约随「层数 × 窗口」增长；Bounded Replay 只补一个窗口，将 SWA 截断在片段内，用近似状态换取有界成本。全局分支仍可读取片段外的历史。

\[ \text{从位置 } s \text{ 开始回放时，位置 } i \text{ 的 query 只看 SWA keys} \in \big[\max(s,\, i-W+1),\; i\big] \]

Encoder Bounded Replay：服务于缓存恢复

适用场景：全局 KV 命中，但 encoder SWA KV 缺失。做法是回放已缓存前缀的最后 128 个 token，与未缓存的后缀一起处理。回放部分只重新生成 SWA KV，复用全局 KV，不重算也不覆盖。

效果：前缀缓存只依赖全局 KV，SWA KV 可以彻底移出持久化缓存。

Decoder Bounded Replay：服务于 prefill 减半

每次 prefill 将 prompt 最后 128 个位置的 encoder 输出送进 decoder，补齐近似 SWA KV，并计算用于预测下一个 token 的末尾输出。这些 KV 保留用于本次 decode，但不进入前缀缓存；连续生成时正常更新，不逐 token 回放。

后训练模拟同样的回放，让模型适应近似；不意味着恢复成完整前向的精确状态。

两级 KV 存储

层级内容位置生命周期理由
持久层全局 KV（main KV + indexer K）SSD 持久化缓存保证 ≥ 72 小时长尾复用，前缀可能隔很久才再次命中
短期层Encoder SWA KV分布式内存池（每台机器拿出 10% 的 host DRAM）TTL 分钟级只在活跃会话的下一轮内复用，会话结束即失效
1/8 是两个因子相乘的结果V4 的持久化 KV 中，SWA KV 约占一半。把它移走，容量约减半（×1/2）；全局 KV 本身又缩到 1/4。两者相乘：\(\tfrac12\times\tfrac14=\tfrac18\)。V4 原本提出的 Zero SWA Caching 需要精确回放 \(L\times n_{\text{win}}\) 个 token，在生产中太贵。Bounded Replay 把一次严重的缓存未命中变成了代价很低的近似恢复。

07Single-Pass mHC

mHC（Manifold-constrained Hyper-Connections）在相邻 block 之间维护 \(n\) 条残差流。V4.1 中 \(n=4\)，Sinkhorn-Knopp 迭代 20 次。

\[ X_{l+1} = B_l X_l + C_l\,\mathcal{F}_l(A_l X_l),\qquad (A_l,B_l,C_l)=\mathcal{H}(X_l) \]

问题在于：输入混合 \(A_lX_l\) 必须等 \(\mathcal{H}(X_l)\) 对整个隐藏维度完成归约之后才能开始，所以残差数据要读两遍。Single-Pass mHC 只改了一个下标：

\[ X_{l+1} = B_l X_l + C_l\,\mathcal{F}_l(\color{#fb7185}{A_{l-1}}X_l),\qquad (A_l,B_l,C_l)=\mathcal{H}(X_l) \]

当前 block 使用上一个 block 预测的输入混合系数，数据依赖随之消失。kernel 遍历 \(X_l\) 的每个 tile 时，可以同时完成输入混合，并累积下一步预测系数所需的统计量。实验中这个偏移带来的性能损失可以忽略。

\((2n+2)d\) 正是理想下界：\((n+1)d\) 次读加 \((n+1)d\) 次写。Mega-mHC 把残差更新、输入混合、系数预测、input pre-norm 和 FP8 转换融合进一个 kernel。预训练仍使用多 kernel 实现，部署时才拿到访存收益。

相对原版 Engram 的改动

  • 去掉 short causal convolution：在 DeepSeek 的推理栈里，它带来的收益抵不上增加的复杂度。
  • 换优化器：嵌入表改用「动量 + Sinkhorn balancing」更新（见第 12 节），只需一个动量缓冲。学习率是主干的 5 倍。

部署特性

  • 查表地址只取决于输入 token，可以提前确定，因此推理时通过后台 RDMA 从 host 内存预取，与计算重叠。第一个模块的预取与第一个 Transformer block 的计算重叠。
  • RL rollout 期间，Engram 表常驻 GPU，避免 host 内存碎片导致 OOM。
  • 社区实测（SGLang）：把 Engram 表 offload 到 host，可让 KV 容量提升 36%，吞吐基本不变。

09DSpark 投机解码（取代 MTP）

12优化器：Muon + head-wise Muon + Sinkhorn

参数类别优化器要点
主干线性层、Engram 投影、视觉-语言 projectorMuonNesterov 动量 0.95，解耦 weight decay 0.1；每个更新矩阵的 RMS 缩放到 0.18，以便沿用 AdamW 的学习率
Q / K 权重head-wise Muon按 head 切分后再做正交化。把 Muon 看作预条件梯度下降，原版 Muon 让所有 head 共用一个预条件器，head-wise 版本则每个 head 各用一个，更能适应 head 之间的异质性（GLM-5、Kimi-K3 也验证过）
Engram 表、token embedding、prediction head动量 + Sinkhorn balancing流程与 Muon 相同，只是把 Newton-Schulz 换成行列交替归一化（K=11 次）。只需一个动量缓冲（Adam 需要两个状态），实验中效果也优于 Adam
RMSNorm 权重、bias、scale 等AdamWβ=(0.9, 0.95)，ε=1e-20，wd=0.1（bias 和 scale 不做 decay）

Sinkhorn balancing 寻找对角缩放矩阵 \(D_r, D_c\)，让更新矩阵的行 RMS 和列 RMS 都近似为 1：

\[ \Delta_t = \sqrt{n}\,D_r\,\widehat{G}_t\,D_c,\qquad \tfrac1n\textstyle\sum_j(\Delta_t)_{ij}^2\approx1,\quad \tfrac1m\sum_i(\Delta_t)_{ij}^2\approx1 \]
算法 1：带 Sinkhorn balancing 的动量更新（展开） 
M_t   ← β·M_{t-1} + (1-β)·G_t
Ĝ_t   ← β·M_t + (1-β)·G_t                 # Nesterov
ρ_i   ← ||Ĝ_t[i,:]||₂ ;  ρ̄ ← mean(ρ)
U⁽⁰⁾  ← Ĝ_t ;  U⁽⁰⁾[i,:] ← 0  if ρ_i ≤ τ·ρ̄   # 屏蔽近零行 (τ=1e-3)
for k = 1..K (K=11，奇数):
    odd  k: 每一行除以自身 L2 范数        # 行 = 一个 token / n-gram
    even k: 每一列除以自身 L2 范数        # 列 = 一个隐藏特征
Δ_t   ← √n · U⁽ᴷ⁾                         # 单位行范数 → 单位行 RMS
W_{t+1} ← W_t − γ·η_t·Δ_t                 # γ = 0.18，对齐 Adam 的更新幅度
直觉嵌入类矩阵天然具有「token × 特征」的二维结构，行列交替归一化正好利用了这种结构。Engram 有 196B 参数，用 Adam 的话两份状态的显存开销很大，省掉一份影响显著。

13预训练：数据与日程

文本数据：关注「信息增量」

  • 弱模型生成的内容和低质量机翻被视为隐性重复（implicit duplication）并过滤，因为它们只是改写已有信息，长期训练下可能有害
  • 按模型规模和数据量设计 scaling ladder，逐级校准数据配比
  • 引入更多领域专家，构建细粒度的质量维度；探索 model-in-the-loop 数据迭代
  • 加入更新的代码：新开源仓库、commit、库和框架

多模态数据：成本递增的漏斗

  • 发现爬虫偏向纯文本页面，于是从 Common Crawl 重新引导抓取
  • 不做大规模合成，优先清洗、使用原生的 web 数据
  • 交错图文流程：启发式与统计过滤 → 去重 → 质量模型（以上都在下载图片之前）→ 组装序列 → 图像感知的过滤与去重 → SmolVLM 严格打分 → 淘汰文档部分回收为图文对

训练日程（45T tokens，batch 固定为 100.6M tokens/step，全程无不稳定）

16DSec：百万级并发沙箱

放弃 Kubernetes

自研放置引擎用弱一致性换扩展性：多个副本之间不做同步，各自根据近期测量预测资源并独立决策；节点在本地执行硬性准入检查，作为兜底。计算节点按 shard（scale unit）划分，缩小故障影响范围。

高密度

sub-NUMA 分区，每个 worker VM 绑定一个 NUMA 域。单节点的并发容器数从约 1,000 提升到 2,500+。延迟敏感任务单独设执行类：其他任务用 SCHED_IDLE，再配合 core scheduling 隔离超线程。

约束「坏」Agent

观察到的行为：利用 XFS 驱动权限问题、AppArmor 非法内存访问、从包镜像服务泄露答案，甚至删除关键二进制或整个文件系统。防御手段：每个沙箱单独的 AppArmor 配置 + 基于 eBPF 的网络策略。把环境弄崩的轨迹记为失败，并向 RL 回报 repercussion 信号。

17可控推理强度（Reasoning Effort 1–100）

在 system prompt 中加入 Reasoning Effort: {effort} (range 1–100; …)。训练时对同一个 prompt \(x\) 在多个 effort 档位 \(b\) 下采样，同一 \((x,b)\) 的回答构成子组，在子组内计算 group-relative advantage，不同 effort 之间不直接比较。effort 的差异通过长度惩罚体现：

\[ r^{\text{len}}_{b,j} = -\min\!\Big(C_{\max},\; k(b)\,\frac{\ell_{b,j}}{L_{\text{norm}}}\Big),\qquad k(b)=k_0\exp\!\Big(-\frac{b-b_{\min}}{\tau}\Big),\;\tau=\lambda\,\Delta b \]

effort 每增加 \(\tau\)，惩罚系数乘以 \(e^{-1}\)。附录 C 的解释：如果额外推理带来的边际收益随长度指数衰减，那么指数形式的 \(k(b)\) 会让最优推理长度随 \(b\) 近似线性增长。

18异步 RL 基础设施与大规模 OPD

调度：sample 级派发

rollout 和训练部署在同一批 GPU 上，分时复用。报告比较了三种派发粒度：

  • ✗ batch 级：训练指标剧烈振荡
  • ✗ prompt 级：容易被 GRPO 组内的长尾样本卡住
  • ✓ sample 级：新完成的样本数一旦达到下一个 prompt 的 GRPO group size，就派发该 prompt（这些样本可以来自不同组），并发度保持稳定

无缝中断与恢复

  • token 级中断：生成可以在任意 token 边界停下
  • 状态持久化：KV cache 和专家路由按 token 粒度保存，切换 checkpoint 后直接复用，不用重新 prefill
  • sample 粒度回收：样本结束即释放状态
  • concatenated routing-replay：跨 checkpoint 的样本，把各段 rollout 的专家路由拼接起来，不丢弃也不重算

两类偏差的处理

  • 长度偏差（短样本先返回）：按数据集限制并发；丢弃训练早期过快返回的短样本
  • Off-policy：通过派发和等待逻辑限制最大 off-policy 比例；在 loss 中屏蔽过度陈旧的 token

40+ 教师的全词表 OPD

  • 后训练的最后阶段，覆盖所有领域
  • 各领域的最佳教师可能来自不同开发阶段，架构也可能不同（与学生之间、教师之间都可能不同）
  • 支持数量几乎不受限的异构教师，切换成本可以忽略
  • 训练中动态调整数据配比、各数据集的并发上限和启用的教师；在异步场景下保证配置切换的一致性

21局限与思考

报告承认的边界

  • CSA2 的选择错误：L21 的候选池决定了后续层能看到哪些位置。远距离的关键信息如果没进入池子，后面的层就无法补救
  • Bounded Replay 的近似状态：缓存命中的位置不同，后缀的 KV 在数学上也不同；多次暂停和恢复之后的鲁棒性有待压测
  • 知识容量：SimpleQA、长上下文 LongBench-V2 等仍落后于 V4-Pro
  • 最难的任务：Terminal-Bench 3.0/4.0、ProgramBench 上与最强闭源模型仍有明显差距
  • 架构、语料、规模和训练量同时变化，各组件的单独收益缺少消融实验

值得记住的设计哲学

  • 按复用时间尺度分配存储：全局 KV 长尾复用，放 SSD；SWA KV 只在分钟级复用，放 DRAM 并配合回放
  • 用少量重算换大量存储：Bounded Replay 用 128 个 token 的回放，换来 SWA KV 不再持久化
  • 区分输入和输出的算力：CED 让读和写使用不同的激活规模
  • 训练感知的部署近似：候选池、FP4 QAT、Decoder Replay 都在后训练中模拟
  • 后训练的瓶颈是数据和环境：任务三元组、多 Agent 出题与质检、百万级沙箱
